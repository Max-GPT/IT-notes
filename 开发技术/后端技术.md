# jar包 / war包

- JAR = Java 程序包（Java Archive）
- WAR = Web 应用包（Web Application Archive）

它们本质上都是ZIP压缩包，只是用途不同。

### jar包
运行方式：
java -jar myapp.jar
```
Java程序
    │
    ├── 打包成 JAR
    │
    └── 双击/Java命令运行

包括：

myapp.jar
├── META-INF
│     └── MANIFEST.MF
│
├── com/
│     └── example/
│            Main.class
│            User.class
│
└── lib（有时候）
```

### war包
运行方式：
java -jar myapp.jar
```
Java Web项目
    │
    ├── 打包成 WAR
    │
    └── 部署到 Tomcat

包括：

myapp.jar
├── META-INF
│     └── MANIFEST.MF
│
├── com/
│     └── example/
│            Main.class
│            User.class
│
└── lib（有时候）
```

### 区别对比:
|JAR|WAR|
|--|--|
|Java程序|Java Web应用|
|给 JVM 运行|给 Tomcat 等 Servlet 容器部署
|可以 java -jar|一般部署到服务器运行
|内容主要是 class|class + HTML + JSP + CSS + JS 等
|一般有 Main 方法|一般没有 Main 方法（传统项目）

## 如何打包?
- 假设公司开发一个 OA 系统
- 开发完成后：Maven：mvn package
```
target/
└── oa-system.war

复制
↓
Tomcat/webapps
↓

↓
网站上线
```
- 如果开发的是一个工具：Excel导入工具 / 日志分析工具 / 数据库同步工具
- 完成后：Maven：mvn package
```
tool.jar

运行: 
java -jar tool.jar
```

## 为什么有的项目打包出来也是jar包?
因为 Spring Boot 把 Tomcat 内嵌进了 JAR。

以前（传统 Java Web）：
```
项目(WAR)
↓
Tomcat
↓
JVM
```

现在（Spring Boot）：
```
项目(JAR)
   │
   ├── 内嵌Tomcat
   └── Java代码
↓
java -jar
↓
Tomcat自动启动
```
所以一个 jar 文件就已经包含了 Web 服务器，不需要另外安装和部署 Tomcat。

# Tomcat 
### 第一阶段：只有 Java 程序（没有网站）
```
最开始，Java只能写普通程序。

public class Main {
    public static void main(String[] args){
        System.out.println("Hello");
    }
}
```
Java JVM只负责：

“把Java代码运行起来。”
它不会帮你处理网络请求。

### 第二阶段：网站开始流行
```
服务器必须：
收到HTTP
↓
解析HTTP
↓
找到对应代码
↓
执行Java代码
↓
返回HTML
```

可是Java程序不会这些。
于是大家开始自己写：
```
Socket
↓
解析HTTP协议
↓
自己管理连接
↓
自己返回HTML
```

### 第三阶段：Tomcat诞生

Tomcat其实就是：HTTP服务器 + Java Web运行环境。

```
Tomcat负责：
监听8080端口
↓
接收浏览器请求
↓
解析HTTP
↓
建立Request对象
↓
建立Response对象
↓
调用你的Java代码
↓
返回浏览器
```

# Lombok
- 自动生成 Getter Setter 构造函数等样板代码的 Java 工具
- 用来减少重复代码
- 编译期间自动生成 Getter Setter 之类的机械性代码

使用前
```
public class User {
    private String name;
    private Integer age;

    // Getter
    // Setter
    // toString
    // equals
    // hashCode
    // Constructor
}
```

使用lombok后
```
@Data
public class User {
    private String name;
    private Integer age;
}
```

# postman
- Postman 是 API 测试工具。
- 它的作用可以一句话概括：不用写前端页面，也不用写浏览器代码，就可以直接向服务器发送 HTTP 请求，查看服务器返回什么。

### 为什么会产生 Postman？
```
浏览器
    │
HTTP请求
    │
Tomcat
    │
Spring Boot
    │
数据库
```

但是开发后端的时候，前端可能还没做好。或者：我只是想测试一下接口有没有问题。难道每次都要写一个网页吗？太麻烦了。

于是就需要一个工具：能够模拟浏览器发送 HTTP 请求。这就是 Postman。

### 它到底做什么？
例如你的 Spring Boot 有一个接口：
```
POST /login
```

Postman 可以直接发送：
```
POST http://localhost:8080/login
{
    "username":"zhangsan",
    "password":"123456"
}
```

服务器收到以后：

```
Spring Boot
↓
验证账号
↓
返回JSON
```

Postman 会直接显示：
```
{
    "code":200,
    "message":"登录成功"
}
```

整个过程：
```
Postman
↓
HTTP请求
↓
Tomcat
↓
Spring Boot
↓
数据库
↓
JSON
↓
Postman
```

### HTTP 常见请求：

|方法|作用|
|--|--|
|GET|查询数据
|POST|新增数据
|PUT|修改数据
|DELETE|删除数据

# Poderosa
一个连接 Linux 服务器的“远程黑窗口工具”。

### Poderosa主要做什么？
1. SSH连接服务器
2. 查看日志（日本IT现场非常常见）
3. 启动 / 停止系统
4. 操作服务器文件

```
你的电脑
    ↓
Poderosa
    ↓ SSH
远程服务器
```

```
你的开发PC
    │
    │ SSH连接
    ▼
Linux服务器
    │
    ├── Tomcat
    ├── Spring Boot
    ├── Java
    ├── Log文件
    └── 数据库
```
